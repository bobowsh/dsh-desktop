## github.com hosts IP 443 不通导致 pnpm 拉 github 包卡住（排障）
- 现象：UI 更新 `@dsh-external/dsh-automation`(github:titanwings/dsh-automation) 报"更新失败"，pnpm 栈来自 corepack v11.21.0；pnpm 用系统 pnpm（非项目 pnpm.cjs），设 CI=true。
- 根因：hosts 把 `github.com` 指向 `20.205.243.166`，该 IP **ICMP 通但 443 TIMEOUT**（HTTPS 不通）→ pnpm 对 `https://github.com/...` 发 HEAD 请求一直重试→UI 卡住。ping 正常极易误判为"网络没问题"。实测 `20.27.177.113:443` OPEN、`20.205.243.168/20.27.177.114` 也 OPEN、`166` CLOSED。无系统/全局代理配置。
- 修复：临时把 hosts 第35行 `github.com` 从 166 切到 113（其余映射不动）。改后 `github.com:443` 实测 OPEN；代跑 `CI=true pnpm add "@dsh-external/dsh-automation@github:titanwings/dsh-automation"` → `Done in 2.5s`、exit 0。
- ⚠️ 隐患：hosts 自动更新流水线（automation-1786845361078，每小时）若按 ICMP/旧测速判 166 最快，可能再次切回 166 卡住。建议流水线测速必须包含 443 连通性（不只是 ICMP/HTTPS 测速数字），对 443 不通的 IP 直接排除。
- 排障要点：github 相关拉取卡住，**不要只看 ping**，用 `node -e` 的 `net.connect({host,port:443})` 测目标 IP:443 是否 OPEN 才能定位。

## ★ 界面更新失败的真根因：.modules.yaml 绝对路径失配（safe-delete 是误判）

**推翻上面的 safe-delete 结论**（用户明确否认，后经源码+实测确证无关）。界面更新失败的真实根因：

- **现象**：DSH_HOME=data 后，界面里 dshmarket 点"更新"必失败，栈尾是 pnpm 内部异常（`pnpm.mjs:218507` 只是 `recursive()` 中间帧，报错信息在栈**开头**被界面截断）。
- **根因**：`data/profiles/web/node_modules/.modules.yaml` 是 bundle 从 live `cpSync` 拷来的，里面记录的是**源机器绝对路径**（`storeDir=D:\...\pnpm\store\v11`、`virtualStoreDir=D:\...\.dsh\profiles\web\node_modules\.pnpm`）。pnpm 的 `checkCompatibility`（pnpm.mjs:209929-209948）逐字段与当前运行目录比对，不一致即抛 `ERR_PNPM_UNEXPECTED_STORE` / `ERR_PNPM_UNEXPECTED_VIRTUAL_STORE`。
- **pnpm 跨卷 store 规则（源码 pnpm.mjs:182024-182063）**：未显式配置 store-dir 时，若 node_modules 与 home 不同卷（硬链失败），store 自动落到 node_modules 所在卷根 `.pnpm-store\v11`（本机 E:\.pnpm-store）→ 与元数据记录不一致 → 必炸。
- **pnpm 配置读取真相**（实测）：`npm_config_store_dir`/`NPM_CONFIG_STORE_DIR`（env）、profile 内 `.npmrc` 的 `store-dir` **均不生效**（`pnpm store path` 不变）；**只有 `pnpm-workspace.yaml` 的 `storeDir` 生效**（实测 `storeDir: ../.pnpm-store` 被读取）；`--store-dir` CLI 参数也生效。`~/` 前缀会展开 homedir（`getStorePath` 的 isHomepath 分支）→ **可移植方案**。
- **最终方案（已落地并验证）**：
  1. `pnpm-workspace.yaml` 追加 `storeDir: ~/AppData/Local/pnpm/store` → pnpm 显式用当前用户 home store（任意机器展开为本机 home；跨卷导入自动 copy fallback），不再新建卷根 store。
  2. `.modules.yaml`：删 `virtualStoreDir`（可选检查字段，删了 pnpm 重算）；`storeDir` **必须存在且精确匹配**（`!modules.storeDir` 也会抛）→ 由桌面壳 `syncModulesMetadata()`（harness-runtime.ts 新增，启动时幂等执行）写入当前机器路径 `%LOCALAPPDATA%\pnpm\store\v11`。
  3. `bundle-user-data.mjs` 的 `normalizeModulesMetadata`：拷贝后删 `.modules.yaml` 两个字段 + 目标 `pnpm-workspace.yaml` 追加 storeDir（若没有），保证打包产物无机器绝对路径。
- **实测验证**：`CI=true pnpm -C data\profiles\web add dshmarket@latest` → 成功（dshmarket 1.11.1→1.11.3，downloaded 1）；`add dsh-pet@latest` → 成功（0.1.3→0.1.4）；`.modules.yaml` 被 pnpm 重写为 `storeDir=d:\Users\bobowsh\AppData\Local\pnpm\store\v11`（home store，非程序目录）✓；30 个插件全在。
- ⚠️ **教训**：pnpm add/remove 中途被切断会在 staging 中移走部分包（本次 @anionex scope 消失导致 harness 启动失败 `cannot resolve profile bundle`），恢复=从 live `~/.dsh/profiles/web` 整体 cpSync（live 是完好自洽的源）。**不要对 data 的 node_modules 做破坏性操作时中途打断**。
- **链接扫描**：`data/profiles/web/node_modules` 共 7699 文件、729 目录，**symlink 0 个**、硬链接（nlink>1）7421 个 → 无 symlink 指向 store，拷/打包物化为独立文件后自包含，无悬空链接。✓

## node-pty 双份冗余 + native prebuilds 瘦身（安装包 -115M）
- **两份 node-pty 的来源**（都删不得）：① app 侧 `node_modules/node-pty`（依赖链 dsh-desktop→@deepseek-ai/dsh→dsh-base→dsh-subprocess-local，harness 引擎子进程 PTY 必需）；② 插件树侧 `data/profiles/web/node_modules/node-pty`（dsh-better-sidebar 的终端面板依赖）。electron-builder 分别走 `files`（app）和 `extraResources`（data）打包。
- **为什么全平台**：node-pty@1.1.0 的 npm 包**自带** `prebuilds/` 下全部平台二进制（darwin-x64/arm64、win32-x64/arm64，共 58M），不是 optionalDeps，装一个包就全带。其中 **.pdb 调试符号 ~53M 运行时完全无用**；win32-arm64 28M + darwin 200K 对 win-x64 分发无用。
- **瘦身 1（插件树）**：`bundle-user-data.mjs` 新增 `trimNativePrebuilds(webDest)`——通用规则：删所有 `*.pdb` + `prebuilds/` 下非 `win32-x64` 平台目录 + `*/win10-arm64` conpty。node-pty 64M→7.8M，node_modules 整体 218M→164M。⚠️ 教训：rmSync 平台目录在 electron-builder 并行读文件时会瞬占失败，原实现静默吞错导致 arm64 残留——已改为每个 entry 独立 try-catch + `console.warn` 报错（下次 bundle 不会再静默漏删）。
- **瘦身 2（app 侧）**：`package.json` `build.files` 加排除 `!**/*.pdb`、`!**/prebuilds/win32-arm64/**`、`!**/prebuilds/darwin-*/**`、`!**/win10-arm64/**`（已验证 minimatch 匹配：x64 运行时文件 .node/winpty.dll/winpty-agent/OpenConsole.exe 全部保留，pdb/arm64/darwin 全排除）。app 侧 node-pty 再省 ~60M。
- **验证工具**：minimatch v10 是 ESM-only（`require` 返回非函数），必须用 `import { minimatch }` + .mjs；且 electron-builder 的 `!` 前缀是"排除"语义（不是 minimatch negate），验证时要对**去 `!` 的 pattern** 做正匹配。
- 下次打包（build-installer.ps1）后安装包应显著变小（~115M）。

## 执行命令弹黑窗口的根因（dsh-desktop-me + deepseek-harness）
- 桌面壳本身没问题：`src/main/runtime/harness-runtime.ts` 的 `buildHarnessSpawnOptions` 启动 harness 子进程时已设 `windowsHide: true`（第 64 行），不会弹窗。
- 真正弹窗发生在 harness 内部执行命令：
  `dsh-bash-local` → `ctx.subprocess.spawn(spec)` → `@deepseek-ai/dsh-subprocess-local` 的 `spawnSubprocess()`（`node_modules/@deepseek-ai/dsh-subprocess-local/lib/index.js:548`）调用 Node `spawn(program, args, { cwd, env, stdio, detached })` **漏了 `windowsHide: true`**。
- Windows 上 Node 默认 `windowsHide: false` → 每次执行命令都会分配一个可见控制台（黑）窗口。
- 同仓 `dsh-host-directory-picker-native`、`dsh-native-command` 都显式写了 `windowsHide: true`，说明 `dsh-subprocess-local` 这一处是被遗漏的 bug（不是有意为之）。
- 修复：给 `spawnSubprocess` 的 spawn options 加 `windowsHide: true`；用 patch-package 固化成 `patches/@deepseek-ai+dsh-subprocess-local+0.1.0-rc.6.patch`（package.json 的 postinstall 已自动跑 `patch-package`）。一处修复同时覆盖 Bash 与 Shell 两种命令执行（都走 dsh-subprocess-local）。

## 参考 deepseek-harness-desktop（"另一家"）对齐补丁
- "另一家" = `E:\work\deepseek-harness-desktop`，它用 **pnpm `patch:` 协议**（package.json 的 `patchedDependencies`）固化补丁，机制上不同于 dsh-desktop-me 的 patch-package。
- 它**只对** `dsh-sandbox-windows-acl` 打了补丁（Win32 `dwFlags:256→257` + `wShowWindow:0`，在 `spawnSandboxed`/`spawnSandboxedInherited` 两处），**没给 `dsh-subprocess-local` 打**。
- dsh-desktop-me 现有的 `dsh-sandbox-windows-acl` 补丁内容与"另一家"**完全一致**（仅文件名/路径前缀格式不同：patch-package 用 `+` 且路径含 `node_modules/...`；pnpm 用 `@` 且路径只到包内 `lib/...`）。已对齐，无需重复。
- dsh-desktop-me 缺的是 `dsh-subprocess-local`，已用 patch-package 格式补上：`patches/@deepseek-ai+dsh-subprocess-local+0.1.0-rc.6.patch`。端到端验证：还原 node_modules → 跑 `patch-package`（无参数，等同 postinstall 的 apply 环节）→ 9 个补丁全部 ✔，`windowsHide: true` 自动 apply 回（lib/index.js:557）。
- 坑：`dsh-desktop-me/node_modules/.bin/patch-package` 的 shebang 指向 `node_modules/node/bin/node`（给 electron 构建用的 `node` npm 包，Win 上非真二进制），直接 `npx patch-package` 会报 `This: command not found`。绕过：用系统 node 直接跑入口 `NODE_OPTIONS="" <node> ./node_modules/patch-package/index.js <pkg>`（`NODE_OPTIONS=""` 同时规避 WorkBuddy 的 safe-delete 垫片）。
- 同源已补：`dsh-sandbox-local` 的 `spawnSync`（三个平台 probe：bwrap/seatbelt/windows-acl，lib/index.js:114/137/166）也缺 `windowsHide`，会偶发弹窗。已用 patch-package 补上：`patches/@deepseek-ai+dsh-sandbox-local+0.1.0-rc.6.patch`，给三处 options 加 `windowsHide: true`（非 Win 平台该选项被 Node 忽略，无害）。
- **`npm install` 端到端验证（用户要求）**：`NODE_OPTIONS="" npm install` → postinstall 自动跑 `patch-package` 应用**全部 10 个**补丁（原 8 个 + subprocess-local + sandbox-local），新增两处均 ✔；grep 确认 `windowsHide: true` 已写回 node_modules（sandbox-local 三处 114/137/166、subprocess-local 557）。证明以后 `npm install` 不会再把补丁冲掉。`npm install` 必须带 `NODE_OPTIONS=""` 否则会触发 WorkBuddy 的 safe-delete 垫片导致安装异常。

## 为什么 deepseek-harness-desktop（"另一家"）没给 dsh-subprocess-local 打补丁
- 它不是"漏修"，而是**依赖树里根本没有 `@deepseek-ai/dsh-subprocess-local`**：查过它的 `.yarn/cache/*.zip` 与磁盘 `node_modules`，均无此包。它用 Yarn 4 (PnP)，根 package.json 是 workspace，真正的桌面壳在 `dsh-plugin-desktop` 子包；该子包只列了 `dsh-subprocess`（接口）和 `dsh-bash-local`，未列 `dsh-subprocess-local`。
- 对照 dsh-desktop-me：`dsh-subprocess-local` 是**直接依赖**，命令执行 100% 走它 → 弹窗必现，必须 patch。
- "另一家"只 patch 了它确实用到且 Win32 特定的 `dsh-sandbox-windows-acl`（`wShowWindow:0`），因为 sandbox 走 Win32 `CreateProcessAsUserW`，窗口问题必现。
- 结论：两个项目补丁范围不同，**根因是命令执行后端依赖不同**，不是谁修漏了。dsh-desktop-me 当前的补丁（subprocess-local + sandbox-windows-acl）是正确且必要的。

## 打包 dsh.cmd CLI 垫片 + 根目录快捷方式（2026-08-16）
- 需求：打包 `scripts/dsh.cmd`，安装后释放到 **`resources\app\node_modules\node\bin`**（bundled node 的 bin 目录），并在安装根目录留快捷方式。
- 目标布局解析：`extraResources` 加 `{ from: "scripts/dsh.cmd", to: "app/node_modules/node/bin/dsh.cmd" }`（extraResources 前缀 = `resources\`）→ 落到 `<install>\resources\app\node_modules\node\bin\dsh.cmd`。
- **关键点**：这个目标目录里**本就有 node.exe**，且 dsh.cmd 的相对路径 `..\@deepseek-ai\dsh\lib\bin.js` 从 `node\bin` 往上一层正好是 `node_modules\@deepseek-ai\dsh\lib\bin.js`（真实存在）→ **原 dsh.cmd 一个字不用改，ConfigWrite/占位符全不需要**。
- 实现：
  - `install-user-data.nsh` `customInstall`：只 `CreateShortcut "$INSTDIR\dsh.lnk" "$INSTDIR\resources\app\node_modules\node\bin\dsh.cmd" "" "$INSTDIR\resources\icon.png"`；新增 `customUnInstall` 宏 `Delete "$INSTDIR\dsh.lnk"`。
  - ~~bundle-user-data 的 dsh.cmd 占位符暂存~~（最初方案放到 resources\node 时才需要，路径改对后已回滚删除）。
- 教训：释放位置选对（bundled node 的 bin）后，npm shim 的相对路径天然成立，最省事。最初误放 `resources\node\` 导致 `..` 指错，还得改写路径——位置对了就不用改。
- 验证：全量 `NODE_OPTIONS="" npx electron-builder --win --x64 --publish never` **EXIT=0**，双分支编译干净；产物确认 `resources/app/node_modules/node/bin/dsh.cmd` 就位、同目录 node.exe 在、相对路径 `../@deepseek-ai/dsh/lib/bin.js` RESOLVES、内容无占位符（原始版）、setup.exe 218MB 重建。

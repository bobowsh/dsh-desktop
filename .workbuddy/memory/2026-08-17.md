- 问题：app 的 market installer 内置 `pnpm` 依赖 pin 在 `10.34.5`（→ store v10），而 web profile（`~/.dsh/profiles/web`）是用用户全局 pnpm 11 装的（hoisted + store v11），导致 app 内「更新 dshmarket」失败（store/版本不一致 + supply-chain policy）。

- 打包影响：electron-builder `files` 含 `node_modules/**/*`，嵌套 pnpm 会进安装包 → 终端用户安装器也自带 pnpm 11.21.0，全链路对齐 v11。

## 修正：连接手机按钮是 preload 注入的 DOM，不止 main 菜单（用户报"主界面还有按钮"）
- 用户反馈：重启后仍能在主界面看到「连接手机」按钮。排查发现该按钮是 **`src/preload/index.ts`** 用 `MutationObserver`（`mobileButtonObserver`）注入进侧边栏 footer（`[data-dsh-sidebar-footer]`）的 DOM 元素（`mountMobileButton()`/`renderMobileButton()`，L29-67、`initializeUi` L79-90），与 main 进程的原生菜单是**两套独立渲染**。之前只在 `src/main/index.ts` 关了菜单+IPC，preload 那层完全没动，所以按钮一直显示（点了虽因 IPC 返回 undefined 无反应，但看得见）。
- 修正（单一开关源）：新建 `src/shared/features.ts` 导出 `export const ENABLE_MOBILE_BRIDGE = false`；`src/main/index.ts` 与 `src/preload/index.ts` 都改为从 `../shared/features` import，删掉各自本地的 `const` 副本。
  - preload 两处把关：`mountMobileButton()` 开头 `if (!ENABLE_MOBILE_BRIDGE) return`；`initializeUi()` 把 `mountMobileButton()` + `mobileButtonObserver.observe(...)` + `refreshMobileStatus()` + 定时器整体包进 `if (ENABLE_MOBILE_BRIDGE) { ... }`。这样禁用时连 `mobile:status` 轮询都不发、按钮永不挂载。
- 验证：`tsc --noEmit -p tsconfig.node.json`（覆盖 src/main、src/preload、src/shared）零报错。随后用 **PowerShell 工具**（不能从 bash 调 powershell，会被安全策略拦）跑 `build-installer.ps1`，并 `NODE_OPTIONS=""` + 关沙箱（构建要 spawn NSIS/makensis，且 safe-delete 垫片会让 electron-builder 死锁）。
- 经验：**禁用某个"功能"时，凡是有 UI 入口的，必须同时查 main（原生菜单/IPC）和 preload（注入到网页 DOM 的按钮/组件）两层**，否则会漏掉可见入口。

## 修复「选择文件/目录对话框弹不出来」（PR #55 fix-electron-directory-picker）
- 根因：DSH 原用 Koffi native 目录选择器 worker（`dsh-host-directory-picker-native`）。Windows 打包版 Electron 中该 native worker 子进程会在 report 结果前提前退出 → 对话框根本不弹。中间曾用 `dsh-host-directory-picker-auto` patch 把 Windows 强制切 `browse` 后端，但 browse 是 web/remote 兜底、桌面单机不可达，依旧不行。
- 最终方案（`46f7d3f` Use Electron system directory picker）：改用 Electron 自带系统对话框，彻底绕开 Koffi。
  - `src/main/index.ts` 新增 `ipcMain.handle('directory-picker:open', ...)` → `dialog.showOpenDialog(mainWindow, {properties:['openDirectory']})`；带 mainFrame 来源校验防越权。
  - `src/preload/index.ts` 用 `contextBridge.exposeInMainWorld('dshDesktopDirectoryPicker', { pick: () => ipcRenderer.invoke('directory-picker:open') })`。
  - `patches/@deepseek-ai+dsh-client-ui-directory-picker-native+...patch`：UI 端 directoryFlow 改调 `window.dshDesktopDirectoryPicker.pick()`，桥不可用即 reject。
  - `build/dsh-desktop.patch.yml`：`directory-picker` 保持 `disabled: true`；insert 项由 host native 改为 `directory-picker-electron-desktop-surface`（client UI 表面）。
  - 删除 `patches/@deepseek-ai+dsh-host-directory-picker-auto+...patch`。
- 收尾（`d8d1338` reconcile native directory picker integration）：由于不再加载 host directoryPicker 服务，`@deepseek-ai/dsh-host-apiproxy` 的 `pickDirectory/listDirectory/createDirectory` 原本直接 `ctx.directoryPicker` 会报错、拖垮整个 proxy。改为 `const directoryPicker = ctx.get("directoryPicker"); if (!directoryPicker) return err(..., {code:"directory-picker-unavailable", details:{capability:"none"}})`；并从 `ApiProxyService` 依赖声明移除 `"directoryPicker"`。
- 调用链：UI directoryFlow → `dshDesktopDirectoryPicker.pick()` → preload IPC `directory-picker:open` → 主进程 `dialog.showOpenDialog` → 系统对话框弹出。host 端接口降级为"不可用即报错"，不再阻塞 proxy。

## mnemon.cliPath 改走 MNEMON_CLI_PATH 环境变量（相对 exe，不再写死）
- dsh-mnemon 的 `expandHome$1` 只展开 `~`（用户 home），harness 的 settings 加载器也不做 `${DSH_HOME}` 插值 → settings.yaml 里**没法写"相对 exe 的路径"**（绝对路径或 `~` 都不满足"跟 exe 走"）。
- 插件 `findMnemonCommand` 优先级：settings.cliPath 存在→直接用（且忽略 env）；不存在→读 `MNEMON_CLI_PATH` env → PATH 搜索 → 常见目录。
- 正确做法：settings.yaml 不写 cliPath，改由桌面壳在 `buildHarnessSpawnOptions` 注入 `MNEMON_CLI_PATH: join(dshHome,'bin','mnemon.exe')`（dshHome 已是"exe 旁 data"）。dev/打包都自动跟 exe 走，仓库零硬编码。
- 已改：harness-runtime.ts 注入 MNEMON_CLI_PATH；data/settings.yaml 删 cliPath 行；bundle-user-data.mjs 去掉 `@@MNEMON_CLI@@` 占位符注入（避免构建重新塞回坏占位符）。
- ⚠️ 仍待办：`build/install-user-data.nsh` 的 customInstall 仍把 data 释放到 `$PROFILE\.dsh` 并改写 cliPath（旧方案），与新 DSH_HOME=data 冲突；待重做为"不释放、DSH_HOME=data 直接读程序目录 data"。
